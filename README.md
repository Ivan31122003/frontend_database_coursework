# Система управления сотрудниками, отделами и проектами

Учебный full-stack проект по дисциплине «Базы данных» направления «Программная инженерия» СПбПУ. Это веб-приложение для ведения организационных данных: сотрудников, отделов, проектов и связей между ними.

Проект показывает практическую связку реляционной базы данных, серверного REST API и одностраничного пользовательского интерфейса. В фокусе работы с БД — CRUD-операции, ограничения на уровне PostgreSQL, авторизация и разграничение доступа к данным.

## Возможности

- авторизация пользователя по имени и паролю;
- просмотр, создание, редактирование и массовое удаление сотрудников;
- управление отделами и проектами;
- ведение связи «сотрудник — отдел»;
- просмотр пользователей в административном разделе;
- ограничение доступных операций согласно правам пользователя;
- уведомления об успешных действиях и ошибках;
- выгрузка отчёта «сотрудники — проекты» в файл `.xlsx`.

## Архитектура

```text
Vue 3 SPA
    |
    | HTTP / JSON
    v
Express REST API
    |
    | SQL через pg
    v
PostgreSQL
  ├── таблицы сотрудников, отделов и проектов
  ├── связь сотрудников с отделами
  ├── пользователи и права доступа
  ├── функции выборки и проверки доступа
  └── триггеры с бизнес-ограничениями
```

Клиент хранит JWT в cookie и передаёт его API при выполнении защищённых операций. Сервер взаимодействует с PostgreSQL через пул соединений. Кроме аутентификации, доступ к маршрутам проверяется функцией БД `admin.check_route_access(user_id, route)`.

## Предметная область и данные

Приложение работает со следующими сущностями:

| Сущность | Назначение |
| --- | --- |
| `employees` | Сотрудники: ФИО, должность и заработная плата |
| `departments` | Подразделения организации |
| `projects` | Проекты: стоимость, ответственный отдел и плановые/фактические даты |
| `departments_employees` | Связь сотрудников с отделами |
| `admin.users` | Учётные записи для входа в систему |

Для формирования отчёта используется функция БД `get_employees_projects()`. Ошибки ограничений, возвращаемые триггерами PostgreSQL, обрабатываются сервером и выводятся пользователю в интерфейсе.

## API

Все рабочие маршруты API используют префикс `/api`. Основные группы конечных точек:

| Группа | Примеры маршрутов | Назначение |
| --- | --- | --- |
| Авторизация | `POST /api/auth` | Проверка учётных данных и выдача JWT |
| Сотрудники | `POST /api/employees/{get,put,update,delete}` | Операции с сотрудниками |
| Отделы | `POST /api/departments/{get,put,update,delete}` | Операции с отделами |
| Проекты | `POST /api/projects/{get,put,update,delete}` | Операции с проектами |
| Связи | `POST /api/departments_employees/{get,put,update,delete}` | Назначение сотрудников в отделы |
| Отчёт | `POST /api/employees_projects/get` | Данные для экспорта в Excel |
| Администрирование | `POST /api/users/get` | Список пользователей |

## Запуск

### Клиент

Для запуска интерфейса нужны Node.js и npm:

```bash
cd frontend
npm ci
npm run dev
```

Vite выведет адрес приложения в терминале; по умолчанию это `http://localhost:5173`. Сборка production-версии выполняется командой:

```bash
cd frontend
npm run build
```
